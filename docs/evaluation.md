# Phase 4 evaluation contract

Megamind v0.5 ships two offline evaluation surfaces.

## Release benchmark

`megamind-axi bench run --fixtures evals/fixtures/release-mini --queries evals/queries.jsonl --thresholds evals/thresholds.toml --out results.json --repeat` invokes the public `preflight` and `route` interfaces for every frozen synthetic query. It emits one canonical `megamind/benchmark-result/v1` document and never calls a model or network. `bench check` evaluates the same machine-readable thresholds. Tiers are reported independently: exact, near, paraphrase, ambiguous, no-match, and privacy. Private canary strings are invented and only safety counts are emitted.

A query set must carry a registered `megamind/benchmark-query-set/v1` header declaring a version and `frozen: true`. The emitted `benchmark_version` is that declared version, never a hardcoded label, so a result can never claim to be the release benchmark when it is not.

### Preregistered thresholds

Thresholds are only meaningful for the inputs they were frozen against, so `evals/thresholds.toml` carries a `[binding]` section naming the benchmark version and the `corpus_sha256`, `queries_sha256`, `task_set_version`, and `task_set_sha256` it gates. `bench run`, `bench check`, and `experiment plan` all refuse a missing, stale, or tampered binding. Post-hoc threshold changes are therefore visible: they change the threshold digest recorded in the result.

### Routing accuracy versus authorized context

Per-tier accuracy measures what the deterministic ladder surfaced (`candidates`). What the declared model class may actually receive is a separate, narrower set (`loaded`), derived from `preflight` for every model class, not only cloud:

- `full` access authorizes the wiki's route ladder;
- `digest-only` access authorizes exactly the artifacts preflight lists in `allows`;
- `none` access, pointer-only wikis, and any wiki that preflight only *offered* (which includes every provisional wiki and every ambiguous choice) authorize nothing.

Context accounting, canary scanning, and the model-access counter all run over `loaded` only. `model_access_violations` re-derives each loaded artifact's posture from `megamind.access`, the single authority, so a disagreement between preflight and the policy module is reported rather than hidden.

Each query may also pin `expect_status` and `expect_loaded`. Those are behavior contracts, not quality metrics: a mismatch counts into `contract_violations`, which is gated at zero.

### The fixture

`evals/fixtures/release-mini` is generated by `evals/gen_corpus.py`, which is the only source of its bytes; `tests/test_evaluation.py` regenerates into a temporary directory and requires an exact match. Regenerate with `python evals/gen_corpus.py evals/fixtures/release-mini --replace`, then update `corpus_sha256` in `[binding]`; the bound-digest test names the new value when it fails.

The corpus exercises routing cards, indexes and exact pages, a digest-only wiki with mixed-language content, a pointer-only wiki, a company-private wiki whose cloud access is none, a provisional wiki, and page sizes that make the context budget bind. Canary pages exist on disk but are linked from no index and no digest, so the ladder must never reach them - while the grep and full-vault baselines do, which is what makes the baseline contrast honest rather than decorative.

The fixture, query set, threshold file, and task-set versions are immutable release inputs. Do not change a released version in place. Add a versioned file and update the release notes when a threshold or task changes. The grep and full-vault baselines are context/safety baselines, not claims of model quality.

## Three-arm value evaluation

`experiment plan` freezes the task-set digest, prompt inputs, model/provider identifier, tools, effort, rubric, thresholds, seed, and isolated no-wiki/current-wiki/updated-wiki snapshot roots. It emits three artifacts:

- the plan (`--out`), which names blind labels, snapshot digests, and isolated output roots but never says which label is which condition;
- the grader packet (`--grader-out`), which carries only the blind labels, the task prompts, and the rubric - no seed, no snapshot digest, no condition;
- the unblinding map (`--map-out`), a host execution artifact that maps labels to conditions.

Conditions are assigned to labels by a deterministic permutation derived from the seed and the frozen input identity, so a different seed produces a different assignment and the same plan always reproduces its own. Whoever grades the arms must never hold the map.

The host executes identical pre-authored tasks and writes arm outputs; Megamind never invokes a model, worker, account, service, or network.

The host then submits one output per opaque arm to `experiment validate`, which needs no map. Validation rejects missing or duplicate tasks, wrong snapshot digests, changed plan/task versions, malformed context accounting, privacy/model-access violations, canary or prompt leakage, and incomplete arms. `experiment score --unblinding-map <file>` scores every arm by its blind label first, seals the result as `blind_scores_sha256`, and only then reads the map; a map that does not match the frozen plan is refused. Scoring applies only the frozen rubric and promotion thresholds. Promotion needs target improvement, no material adjacent regression, preserved provenance within the preregistered tolerance, and zero safety violations. Incomplete evaluations return a typed `unsettled` document and are never promoted; failed gates are `rollback-required` with a non-empty rollback reference. `experiment record` appends a hash-chained, bounded safe event to `.megamind/audit/evaluations.jsonl`; it contains no prompts, answers, canaries, secrets, or sensitive content.

## Where evidence may be written

Every `--out`, `--grader-out`, and `--map-out` destination is resolved and refused when it lands inside an evaluated fixture, snapshot, or audit root, or inside any vault. Evaluation evidence never mutates the thing being measured and never enters wiki-owned space unbacked-up and unaudited. All of these are atomic external writes.

Evaluation output is evidence, not authorization to dispatch a worker or publish a wiki. Provisional wikis remain untrusted until the complete evaluation pass and an explicit governed card change.
