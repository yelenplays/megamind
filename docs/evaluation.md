# Phase 4 evaluation contract

Megamind v0.5 ships two offline evaluation surfaces.

## Release benchmark

`megamind-axi bench run --fixtures evals/fixtures/release-mini --queries evals/queries.jsonl --thresholds evals/thresholds.toml --out results.json --repeat` invokes the public `preflight` and `route` interfaces for every frozen synthetic query. It emits one canonical `megamind/benchmark-result/v1` document and never calls a model or network. `bench check` evaluates the same machine-readable thresholds. Tiers are reported independently: exact, near, paraphrase, ambiguous, no-match, and privacy. Private canary strings are invented and only safety counts are emitted.

A query set must carry a registered `megamind/benchmark-query-set/v1` header declaring a version and `frozen: true`. The emitted `benchmark_version` is that declared version, never a hardcoded label, so a result can never claim to be the release benchmark when it is not.

### Preregistered thresholds

Thresholds are only meaningful for the inputs they were frozen against, so `evals/thresholds.toml` carries a `[binding]` section naming the benchmark version and the `corpus_sha256`, `queries_sha256`, `task_set_version`, and `task_set_sha256` it gates. Every `*_sha256` must be a 64-character hex digest. `bench run`, `bench check`, and `experiment plan` all refuse a missing, stale, or tampered binding. Post-hoc threshold changes are therefore visible: they change the threshold digest recorded in the result.

Every gate is validated before anything is scored, checked, or written. `[release]` must preregister all eight gates and `[promotion]` all three; an unknown key is a typo that would silently leave a gate at its default and is refused, and a missing key would leave an accuracy floor at zero, which passes by construction. Accuracy floors and regression tolerances must be finite numbers in `[0.0, 1.0]`; the `*_max` counters must be non-negative whole numbers, so a fractional `0.9` is rejected rather than truncated to `0`. `bench run` applies these checks too, so a malformed threshold file never produces a result document, let alone writes one.

### Determinism of the measured ladder

The measured `preflight` and `route` invocations inherit the caller's `PYTHONHASHSEED` rather than pinning it. Pinning would certify the harness instead of the ladder, hiding exactly the set-iteration nondeterminism the seed exists to expose. `bench run --repeat` reruns the whole benchmark under a different explicit seed and requires a byte-identical canonical document, so the emitted `deterministic: true` is backed by two seeds rather than by one fixed one.

### Routing accuracy versus authorized context

Per-tier accuracy measures what the deterministic ladder surfaced (`candidates`). What the declared model class may actually receive is a separate, narrower set (`loaded`), derived from `preflight` for every model class, not only cloud:

- `full` access authorizes the wiki's route ladder;
- `digest-only` access authorizes exactly the artifacts preflight lists in `allows`;
- `none` access, pointer-only wikis, and any wiki that preflight only *offered* (which includes every provisional wiki and every ambiguous choice) authorize nothing.

Context accounting, canary scanning, and the model-access counter all run over `loaded` only. `model_access_violations` re-derives each loaded artifact's posture from `megamind.access`, the single authority, so a disagreement between preflight and the policy module is reported rather than hidden.

Each query may also pin `expect_status` and `expect_loaded`. Those are behavior contracts, not quality metrics: a mismatch counts into `contract_violations`, which is gated at zero.

### The fixture

`evals/fixtures/release-mini` is generated by `evals/gen_corpus.py`, which is the only source of its bytes; `tests/test_evaluation.py` regenerates into a temporary directory and requires an exact match. Regenerate with `python evals/gen_corpus.py evals/fixtures/release-mini --replace`, then update `corpus_sha256` in `[binding]`; the bound-digest test names the new value when it fails.

The corpus exercises routing cards, indexes and exact pages, a digest-only wiki with mixed-language content, a pointer-only wiki, a company-private wiki whose cloud access is none, a provisional wiki, and page sizes that make the context budget bind. Canary pages exist on disk but are linked from no index and no digest, so the ladder must never reach them - while the grep and full-vault baselines do, which is what makes the baseline contrast honest rather than decorative.

The fixture, query set, threshold file, and task-set versions are immutable release inputs. Do not change a released version in place. Add a versioned file and update the release notes when a threshold or task changes. The grep and full-vault baselines are context/safety baselines, not claims of model quality.

## Three-arm value evaluation

`experiment plan` freezes the task-set digest, prompt inputs, model/provider identifier, tools, effort, rubric, thresholds, execution seed, and isolated no-wiki/current-wiki/updated-wiki snapshot roots. It takes the host's private blinding key from `--blinding-key-file` (at least 16 characters) and emits three artifacts:

- the plan (`--out`), which names blind labels, isolated output roots, the three snapshot digests as an unordered set, and a keyed commitment to the assignment;
- the grader packet (`--grader-out`), which carries only the blind labels, the task prompts, the rubric, and the same commitment;
- the unblinding map (`--map-out`), a host execution artifact holding the private key, the label-to-condition assignment, and each arm's snapshot root and digest.

Conditions are assigned to labels by an HMAC-SHA256 permutation of the frozen public identity under the private key. The same public inputs and the same key always reproduce the same assignment; a different key produces a different one. The key never enters the plan or the grader packet, so neither public artifact carries inputs sufficient to derive the mapping - and because the assignment space is only 3! = 6 permutations, the commitment is keyed rather than a bare digest, which a holder of the plan could otherwise enumerate. The snapshot digests are published as a sorted set and never beside a label, because an empty no-wiki snapshot has a constant digest that would identify that condition on its own.

The host executes identical pre-authored tasks and writes arm outputs; Megamind never invokes a model, worker, account, service, or network.

The host then submits one output per opaque arm to `experiment validate`, which needs no map and no key. Validation rejects missing or duplicate tasks, snapshot digests that are not among the planned three or that do not cover each planned snapshot exactly once, changed plan/task versions, malformed context accounting, privacy/model-access violations, canary or prompt leakage, and incomplete arms. `experiment score --unblinding-map <file>` scores every arm by its blind label first and seals the result as `blind_scores_sha256`, and only then reads the map. A map is accepted only if it belongs to the plan, opens the plan's commitment under its own key, re-derives the same assignment from that key, and records snapshots matching the planned digests; the per-label snapshot binding is then checked against the submitted outputs. Scoring applies only the frozen rubric and promotion thresholds. Promotion needs target improvement, no material adjacent regression, preserved provenance within the preregistered tolerance, and zero safety violations. Incomplete evaluations return a typed `unsettled` document and are never promoted; failed gates are `rollback-required` with a non-empty rollback reference. `experiment record` appends a hash-chained, bounded safe event to `.megamind/audit/evaluations.jsonl`; it contains no prompts, answers, canaries, secrets, or sensitive content.

## Where evidence may be written

Every `--out`, `--grader-out`, and `--map-out` destination is resolved and refused when it lands inside an evaluated fixture, snapshot, output, or audit root, or inside any vault. `validate` and `score` derive those roots from the validated plan and, for `score`, the validated unblinding map, which is the only artifact naming the arm snapshot roots; an empty no-wiki snapshot is not a vault, so the ancestor scan alone would not catch evidence written into it. The check runs before any work, so a refused destination leaves no partial artifact set and no audit event. All of these are atomic external writes.

Evaluation output is evidence, not authorization to dispatch a worker or publish a wiki. Provisional wikis remain untrusted until the complete evaluation pass and an explicit governed card change.
